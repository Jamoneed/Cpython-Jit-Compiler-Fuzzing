# gh-144681 — lafleur campaign crash

## Summary

Raw crash produced by lafleur's `debug-1` instance on March 20, 2026 at
01:19:51, during the coverage-guided fuzzing campaign against CPython
3.15.0a6+ (commit `6908372fb81`).

This independently reproduced the JIT assertion failure associated with
gh-144681. The bug had already been filed upstream by a CPython contributor
before this crash was recovered, so it is treated as methodology validation
rather than novel discovery. It demonstrates that the repaired lafleur setup
can reach real JIT failure behavior.

## How lafleur reached this crash

The script was generated by the cache-invalidation mutator family
(specifically `CodeSwapMutator`) after 40 sequential mutations from
`seed_async_generators.py`. The triggering pattern is buried inside
`uop_harness_f1` and appears twice in the script.

**The active trigger — `original_code_3716` / `replacement_code_3716`:**

```python
def original_code_3716():
    return 1

def replacement_code_3716():
    return 'a`string'

# Warm up — 102 iterations, unconditional
for i in range(102):
    try:
        res = original_code_3716()
        _ = res + 1
    except Exception:
        pass

# Code object swap
original_code_3716.__code__ = replacement_code_3716.__code__

# JIT traces replacement bytecode with original's stale cache entries
for _ in range(100):
    try:
        res = original_code_3716()
        _ = res + 1
    except Exception:
        pass
```

Step by step:

1. `original_code_3716()` is called 102 times. The JIT builds a trace and
   the Tier 1 interpreter caches bytecode metadata including jump information.
2. `original_code_3716.__code__ = replacement_code_3716.__code__` replaces
   the code object at runtime. This is legal Python.
3. On the next call, the JIT attempts to trace the replacement bytecode. It
   reads the stale inline cache entries from the original. The internal
   `jump_happened` flag and `target_instr[1].cache & 1` from the cache
   disagree on whether a jump occurred at a given instruction offset.
4. The assertion at `Python/optimizer.c:790` fires and the process aborts.

A second instance of the same pattern (`original_code_9338`) also appears in
the script but is gated behind `fuzzer_rng.random() < 0.1`, so it only fires
~10% of the time. The `_3716` instance is the reliable trigger.

---

## Root cause (upstream analysis)

The upstream issue and PR #144742 identify the deeper cause as a trace-builder
branch-direction ambiguity: the failure occurs when a conditional branch target
matches the fallthrough target. The `func.__code__` swap pattern in this script
reaches that failure mode by making the cached jump information inconsistent
with the code being traced.
